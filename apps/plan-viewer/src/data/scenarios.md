# Stage 2 — 정상 동작 시나리오

> **상태**: 검토 대기 · **담당**: Backend · **Stage**: 2/6

요구사항이 충족될 때 시스템이 어떻게 동작해야 하는지를 단계 시나리오로 묘사한다.

## S1 회원가입

- 사용자가 이메일·비밀번호 입력
- `AuthService.signup()` 호출
- 비밀번호 bcrypt 해싱 (cost 12)
- DB 저장
- 인증 메일 발송

## S2 로그인

- 사용자가 이메일·비밀번호 입력
- `UserService`로 사용자 조회
- `HashUtil`로 비밀번호 검증
- `TokenService`로 JWT 발급 (수명 15m)
- 클라이언트에 토큰 반환

## S3 토큰 갱신

- 만료 임박 토큰 감지
- `TokenService.verifyRefresh()`
- 새 access 토큰 발급
- 클라이언트 갱신

## S4 인증 실패

- 잘못된 비밀번호 입력
- 해시 불일치
- 401 응답 + rate-limit 카운트

## S5 로그아웃

- 토큰 폐기 요청
- 세션 종료
- 클라이언트 토큰 삭제

---

> 각 시나리오는 Stage 1의 요구사항(FR/NFR)에 대응한다. 확정 시 Stage 3(모듈 아키텍처)로 진입.
