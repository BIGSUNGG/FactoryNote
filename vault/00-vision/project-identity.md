# FactoryNote 정체성

FactoryNote가 무엇이고, 왜 존재하며, Plannotator와 무엇이 다른지를 정의한다.
아키텍처 상세는 [[multi-agent-pipeline]]을 본다.

## 한 줄 정의

FactoryNote는 **범용 Human-Gated Plan 생성 워크플로 패키지**다.
Codex, Pi, Claude Code 등 다양한 AI 코딩 harness 위에서 동작하며,
AI가 6단계로 나뉜 산출물을 작성하고 사용자가 각 단계마다 검토·수정·확정하는 방식으로
프로젝트 계획을 만든다.

## 해결하는 문제

AI 에이전트는 요청을 충분히 이해하기 전에 코드를 서두르는 경향이 있다.
요구사항 누락, 잘못된 가정, 보안 결함이 코드 깊숙이 박힌 뒤에야 발견되면
수정 비용이 기하급수적으로 늘어난다.

FactoryNote는 이 문제를 **인간 승인 게이트**로 통제한다.
AI가 곧장 코드를 쓰게 두는 대신, 요청 이해부터 검증 계획까지 6단계의
계획 산출물을 순차적으로 작성하게 하고, 각 단계를 사용자가 확인한 뒤에만
다음 단계로 넘어간다.

## Plannotator와의 차이

|        | Plannotator            | FactoryNote                        |
| ------ | ---------------------- | ---------------------------------- |
| 접근     | 구현 계획을 직접(one-shot) 작성 | 6단계로 분해, 단계별 산출물 작성                |
| 사용자 역할 | 결과물을 받아들임              | 각 단계마다 검토·수정·확정                    |
| 통제 지점  | 최종 결과 1회               | 단계별 6회 + Design↔Feedback 내부 루프     |
| 산출물    | 단일 구현 계획               | 요구사항·시나리오·모듈 설계·클래스 설계·구현 계획·검증 계획 |


핵심 차이: **사용자가 프로젝트 구조를 원하는 대로 통제하고 이해할 수 있다.**
AI가 한 번에 내놓는 계획을 수정하는 것이 아니라, 매 단계에서 방향을 잡고
정정하며 계획을 만들어간다.

## 범용성 — harness-agnostic

FactoryNote는 특정 AI 코딩 도구에 종속되지 않는다.

- **Pi** — 루트 `AGENTS.md` + `.pi/skills/doc-workflow` 하이브리드 harness([[ADR-002-hybrid-harness-and-graph-git]]).
- **Codex** — `AGENTS.md` 등가 파일 + 워크플로 규칙 주입.
- **Claude Code** — `CLAUDE.md` + 커스텀 슬래시 명령으로 동일 워크플로 적용.

6단계 워크플로와 멀티에이전트 구조는 harness 중립적이다.
각 harness의 주입 방식(파일명, 스킬 시스템, 명령 체계)만 그 환경에 맞춘다.

## 5대 원칙 (타협 불가)

승인 게이트의 규칙이다. `AGENTS.md` 원문과 동일하며, 각 원칙은 단계 간 경계를 가른다.

1. **승인되지 않은 요구사항으로 설계할 수 없다.** — 요청 이해(Stage 1)가 확정되어야 설계로 넘어간다.
2. **승인되지 않은 설계로 구현 계획을 만들 수 없다.** — 모듈·클래스 설계(Stage 3-4)가 확정되어야 구현 계획을 짠다.
3. **승인되지 않은 구현 계획으로 코드를 작성할 수 없다.** — 구현 계획(Stage 5)이 확정되어야 코드를 쓴다.
4. **승인된 계획과 다른 코드는 검수를 통과할 수 없다.** — 코드는 승인된 계획과 일치해야 한다.
5. **검증되지 않은 코드는 사용자 작업 공간에 반영될 수 없다.** — 검증(Stage 6 기준)을 통과해야 반영된다.

> 원칙 1-2는 계획 단계 간 게이트, 원칙 3-5는 계획→구현→반영 게이트를 가른다.

## 용어집

| 용어 | 정의 |
| ------ | ------ |
| **Harness** | FactoryNote 워크플로를 실행하는 AI 코딩 환경(Pi, Codex, Claude Code 등). |
| **Director Agent** | 각 단계에서 하위 에이전트를 생성하고 Design↔Feedback 루프와 사용자 게이트를 관리하는 조율자. |
| **Design Agent** | 요청을 이해하고 구조를 설계하며 단계별 산출물을 작성하는 에이전트. |
| **Feedback Agent** | 산출물의 보안·병목·구조 문제를 탐지하고 Design Agent에게 재설계를 요청하는 에이전트. |
| **Stage** | 6단계 파이프라인의 각 단계. 고유한 산출물을 갖는다. |
| **Artifact** | 각 단계에서 AI가 작성하고 사용자가 승인하는 산출물(요구사항 명세, 시나리오 등). |
| **Gate** | 단계 간 사용자 승인 검문점. 승인 전에는 다음 단계로 넘어갈 수 없다. |
| **Design↔Feedback 루프** | Design Agent가 산출물을 쓰면 Feedback Agent가 검토하고, 이슈가 있으면 수정을 요청하는 내부 순환. |
