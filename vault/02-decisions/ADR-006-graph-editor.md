# ADR-006: Stage 3/4 다중 섹션 그래프 에디터 — 직접 편집 → 에이전트 채택

## 상태

accepted (데이터 모델은 [[ADR-010-md-design-stage]] 가 보강 — Stage 2 저장 포맷 JSON→md 임베드. 그래프 에디터 UX·채택 원칙은 본 ADR 유지)

## 날짜

2026-08-01

## 맥락 (Context)

MVP([[ADR-005-mvp-implementation]])는 모든 단계를 마크다운으로 렌더하며 Stage 3(모듈)/4(클래스) 그래프 에디터를 연기했다. 사용자 요청: "관계도가 텍스트로만 나오는 문제... 목업의 3/4 페이지처럼 관계도를 편집 가능하게, 추가로 관계도 섹션은 여러 개(예: 프론트/백엔드/프론트-백엔드 인터)". 기존 목업(`ModuleDesign.jsx`/`Classes.jsx`)은 단일 하드코딩 그래프 + 직접 편집(즉시 상태 반영)이며, 설계 문서([[03-design/module-design/features]])는 "본 구현에서는 편집·코멘트를 수정 지시 큐로 처리(5대 원칙)"를 과제로 남겨두었다. 결정이 필요했다: 편집 흐름, 다중 섹션 구조, 데이터 모델, 에이전트의 산출물 포맷.

## 결정 (Decision)

1. **Stage 3/4 산출물 = 다중 섹션 그래프 JSON** — `.factorynote/<feature>/03-modules.json`·`04-classes.json`, 각 `{ sections: [{ id, title, nodes, edges }] }`. 마크다운(`.md`)에서 이탈. 한 단계에 여러 독립 관계도 섹션.
2. **다중 섹션 = 독립 그래프** — 각 섹션은 자기완결. "프론트-백엔드 사이" 같은 교차 관계는 **별도 섹션**으로 표현(섹션 간 엣지 ❌). 에이전트가 초기 섹션을 제안, 사용자가 섹션 추가·이름변경·삭제.
3. **직접 편집 → 에이전트 채택** — 사용자가 노드/엣지를 직접 CRUD(우클릭 메뉴·상세 패널·드래그). 게이트 제출(확정/수정/정정) 시 **편집된 그래프 전체(sections)** 를 `graphSections` 로 POST → `drivePlan` 이 이를 `.json` 산출물로 저장(채택). 확정=다음 단계, 수정=현 단계 유지(+코멘트), 정정=이전 단계.
4. **5대 원칙 조화** — 직접 편집이지만 **게이트를 거쳐 에이전트가 채택**하므로 "승인 전 반영 금지" 위반 아님. 사용자의 편집이 곧 수정 지시(구체적 그래프로 표현). 코멘트는 추가 가이드.
5. **에이전트는 의미 구조 JSON 생성** — 섹션 + 노드 + 엣지의 **의미 구조**만 (`position` 생략 가능). 뷰어가 `position` 누락 시 자동 배치(grid). LLM이 좌표까지 생성하는 부담 제거.
6. **뷰어 = 데이터 주동 `GraphStage`** — 목업의 react-flow 에디터를 `/api/state` 의 `graphSections` 로 구동(하드코딩 제거). Stage 3/4 통일 컴포넌트, 노드 타입·상세 패널·CRUD 가 단계별 분기. 풀패리티(노드/엣지 CRUD, 우클릭 메뉴, 상세 편집, 클래스 parent-child + `NodeResizer`, 코멘트).

## 이유 (Rationale)

- 사용자가 "편집 가능"·"여러 섹션"을 명시 → 목업 UX + 다중 섹션 채택.
- 직접 편집-채택은 그래프 조작(핵심 가치)에 직관적; 게이트 거쳐 채택해 5대 원칙 유지(에이전트가 권위).
- 섹션 독립 = 데이터 모델·UI 단순(node id 전역 유일 불필요, 교차는 별도 섹션).
- 에이전트 의미 구조 + 뷰어 자동 배치 = LLM 부담 최소 + 편집 가능성 확보.
- `.json` 포맷은 그래프 구조에 자연스럽고 `parseGraphArtifact`(코어)가 envelope 검증.

## 대안 (Alternatives)

- **편집 = 수정 지시 명령 큐**(5대 원칙 엄격): 그래프 UX가 무겁고 에이전트 해석 의존 → 기각.
- **섹션 간 엣지 허용**: 표현력 ↑ but node id 전역 유일·UI 복잡 → 기각(별도 섹션으로 충분).
- **단일 그래프/단계**: 사용자 다중 섹션 요구 미충족 → 기각.
- **mermaid 정적**: 편집 불가 → 기각.
- **마크다운 유지**: "텍스트로만" 문제 미해결 → 기각.

## 결과 (Consequences)

- **긍정**: Stage 3/4 가 인터랙티브 다중 섹션 에디터로 동작; 직관적 그래프 편집 + 에이전트 채택; 프론트/백엔드/인터 분리 표현; LLM은 구조만 생성.
- **부정/트레이드오프**: 에이전트가 유효 JSON 생성해야(프롬프트로 안내); 섹션 독립이라 교차 관계는 수동 별도 섹션; 자동 배치는 기본 grid(정교 레이아웃 아님).
- **후속**: 정교 자동 레이아웃(dagre), 섹션 템플릿, 노드 타입 확장(예: 인터페이스/enum).
