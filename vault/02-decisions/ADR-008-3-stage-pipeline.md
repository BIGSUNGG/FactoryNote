# ADR-008: 6단계 파이프라인을 3단계로 통합

## 상태

accepted. [[ADR-005-mvp-implementation]] · [[ADR-006-graph-editor]] · [[ADR-007-pipeline-hardening]] 의 *6단계* 전제를 본 ADR이 정정한다(해당 ADR 전체를 폐기하지는 않는다 — 구현 원리·그래프 에디터·경화 설계는 유효하며, 본 ADR은 단계 카디널리티만 바꾼다).

## 날짜

2026-08-06

## 맥락 (Context)

MVP는 6단계 파이프라인(요청 이해 → 시나리오 → 모듈 설계 → 클래스 설계 → 구현 계획 → 사용자 최종 검증)으로 출하했다. 실사용에서 두 가지 비용이 드러났다.

1. **게이트 과다** — 요구사항↔시나리오, 모듈↔클래스 각각이 별도 게이트라 사용자가 6회 검토해야 한다. 요청 이해 직후의 시나리오, 모듈 직후의 클래스는 같은 맥락에서 한 번에 보는 편이 자연스럽다.
2. **Stage 6(최종 검증)의 중복** — 산출물 간 정합성(요구↔시나리오↔설계↔계획) 총괄 게이트지만, 각 단계 게이트가 이미 순차 승인을 강제하므로 사용자 부담만 늘리고 실제 통제는 추가하지 못한다.

## 결정 (Decision)

파이프라인을 **3단계**로 통합한다.

| Stage | 단계 | 산출물 | 포맷 | 통합 전 |
| ----- | ---- | ---- | ---- | ---- |
| 1 | 요청 이해 · 동작 시나리오 | 요구사항·시나리오 명세 | markdown | 구 1+2 |
| 2 | 모듈 · 클래스 설계 | 설계(모듈·클래스) | nodes-edges(다중 섹션 그래프) | 구 3+4 |
| 3 | 구현 계획 | 구현 순서·의존성 명세 | markdown | 구 5(유지) |

- **Stage 1**: 요청을 이해(요구사항 분해)한 뒤 그에 맞는 정상 동작 시나리오를 *한 산출물 안에서 순차* 작성. 게이트 1회.
- **Stage 2**: 모듈 관계도 섹션과 클래스 구조도 섹션을 *하나의 그래프 산출물*(`02-design.json`)에 함께 담아 한 페이지·한 게이트로 설계. 모듈→클래스 설계 흐름은 섹션 배치로 표현하고, 뷰어는 섹션별 노드 타입으로 종류를 자동 판별(모듈/클래스 공존).
- **Stage 3**: 구현 계획(구 5단계)을 그대로 유지하되 **종료 게이트**로 격상 — 확정 시 파이프라인 완료.
- **구 6단계(사용자 최종 검증)는 완전 폐지**. 정합성 총괄 게이트는 어디로도 이관하지 않는다. `ArtifactFormat`의 `matrix` 포맷도 제거(Stage 6 전용이었음).

## 이유 (Rationale)

- 게이트 수 6→3로 사용자 검토 부담 절반, 동시에 "같은 맥락의 산출물은 함께 본다"는 인지 흐름에 부합.
- 모듈·클래스는 이미 그래프 에디터(GraphStage)가 다중 섹션을 지원하므로, 두 단계를 한 페이지로 합치는 비용이 거의 없다(종류 판별만 노드 타입으로 이동).
- Stage 6 정합성 게이트 제거: 순차 승인이 이미 각 산출물을 검토했으므로, 별도 총괄 게이트의 한계 효용이 게이트 비용보다 작다. 5대 원칙 #5는 Stage 6 앵커를 잃지만, "승인된 계획(Stage 3)에 따라 구현·검증되어야 반영"으로 재서술해 원칙 정신(검증 전 반영 금지)은 유지한다.

## 대안 (Alternatives)

- **정합 점검을 Stage 3(구현 계획) designPrompt로 이관** — 게이트는 줄이되 점검은 보존. 사용자 결정: "완전 폐지" 채택(점검 이관은 하지 않음).
- **모듈·클래스를 2개 파일로 분리하되 한 게이트** — 단일 그래프 파일(`02-design.json`)이 뷰어 재사용 측면에서 더 단순해 기각.
- **3단계 유지 + Stage 6 보존** — 게이트 과다 문제가 남아 기각.

## 결과 (Consequences)

- 긍정: 게이트 3회로 검토 부담 감소, 한 페이지에서 모듈·클래스를 함께 설계, 종료 조건 단순(Stage 3 확정 = 완료).
- 부정/트레이드오프: Stage 1(요구+시나리오)·Stage 2(모듈+클래스) 게이트가 통합되어, 중간 시점의 세분 회귀가 불가능(예: "모듈만 다시" 대신 Stage 2 전체 재검토). 회귀(`revertTo`)는 여전히 Stage 1/2 단위로 동작.
- 후속 작업: `StageId=1|2|3`, `matrix` 포맷 제거, 뷰어(3단계화 + `FinalReview`·죽은 목업 5종 삭제 + 그래프 종류 판별 per-section화), 문서(5대 원칙 #5·파이프라인·정체성·구현 아키텍처) 갱신. 자체체크 49건 green.
