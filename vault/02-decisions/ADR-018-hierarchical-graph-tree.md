# ADR-018: 계층 그래프 트리 + 임의 깊이 드릴다운 뷰어

## 상태

accepted ([[ADR-016-graph-json-externalization]] 를 확장 — 외부 파일화·자동 배치·읽기 전용 원칙은 승계하고, 단일 파일 `sections` 모델을 계층 파일 트리로 교체)

## 날짜

2026-08-11

## 맥락 (Context)

ADR-016 이후 그래프는 산출물당 단일 `02-design-graph.json`(`{sections:[모듈 섹션, 클래스 섹션]}`)이었고 뷰어는 두 섹션을 나란히 렌더했다. 세 가지 한계가 있었다.

1. **규모 확장 불가** — 모듈·클래스가 많아지면 한 캔버스에 전부 그려져 검토가 불가능해진다. 필요한 범위만 펼쳐 보는 드릴다운이 필요하다.
2. **2단계 고정 구조** — 모듈→클래스 섹션 구성이 포맷에 하드코딩되어 있어 메서드 레벨이나 모듈 외 계층(서브시스템→모듈→클래스 등)으로 확장할 수 없다.
3. **단일 파일 비대** — 모든 레벨의 노드가 한 파일에 있어 md 처럼 파일 단위로 분할·검토할 수 없다.

사용자 요구: 기본은 모듈 그래프만 표시 → 모듈 노드 더블클릭으로 해당 모듈의 클래스 그래프를 하단에 추가 → 다른 모듈을 추가 선택하면 클래스 뷰에 병합(모듈 간 클래스 관계 포함) → 재더블클릭으로 선택 해제. 그리고 이것이 모듈→클래스 2단계에 그치지 않고 **모든 노드가 하위 노드 N개를 가질 수 있는 임의 깊이** 구조여야 한다.

## 결정 (Decision)

1. **계층 파일 트리** — 루트는 기존 `<산출물>-graph.json` 그대로(md 의 `<!-- graph: <파일명> -->` 참조 코멘트 불변). 자식이 있는 노드마다 루트 파일명에서 `.json` 을 뗀 서브디렉터리(`<산출물>-graph/`) 안에 파일 1개. 예: `02-design-graph.json` + `02-design-graph/modules/<moduleId>.json` + `02-design-graph/modules/<moduleId>/<classId>.json`. 임의 깊이.
2. **레벨 파일 공통 형태** — `{"version":2, "id":<부모 노드 id, 루트 생략>, "title", "childLevel":<다음 레벨 이름>, "nodes":[...]}`. 노드는 `{id, ...표시 필드, refs, children}` — `children` 은 자식 레벨 파일의 루트 디렉터리 기준 상대경로(자식이 있을 때만). 코어는 envelope(version/nodes/refs 형태/children 경로 안전)만 검증하고 표시 필드는 불투명. `position` 등 좌표 금지(ADR-016 승계).
3. **나가는 참조 모델** — 모든 관계(엣지)는 `refs: [{to, comment}]` 로 **소스 노드 파일에 나가는 방향만** 작성. 단방향=한쪽만, 양방향=양쪽 파일에 각각. `comment`(관계 설명) 필수. 별도 edges 배열 없음.
4. **드릴다운 뷰어** — 레벨 1개=패널 1개. 기본은 루트 레벨. 자식이 있는 노드 더블클릭→하단에 자식 레벨 패널 스택, 재더블클릭→선택 해제(토글). 다중 선택 시 자식 레벨들을 한 패널에 병합(부모 2개 이상이면 부모 그룹 노드 합성으로 소속 유지). **미선택 영역으로의 참조는 숨김**. 임의 깊이 동일 로직(`LevelPanel` 재귀).
5. **서빙은 트리 전체 임베드** — 게이트 서버가 루트에서 도달 가능한 파일을 조립해 `/api/state` 의 `artifacts[].graph.tree`(중첩 레벨)로 서빙. 지연 로딩 없음.
6. **승격은 도달 가능성 순회** — 게이트 오픈 시 draft 트리를 승격할 때 루트에서 도달 가능한 파일만 복사(고아·잔여 제외), 기존 대상 트리는 삭제 후 작성. 회귀(revert)는 루트 json + 서브디렉터리 전체 삭제.
7. **호환 정책 없음** — 구 `sections` 포맷 거부(`version:2` 필수). 기존 확정 산출물 부재로 실질 영향 없음(ADR-016 선례).

## 이유 (Rationale)

- 파일 분리가 md 와 동일하게 리뷰·diff·에이전트 작성 단위를 레벨 단위로 쪼갠다. 에이전트가 트리를 직접 작성하고 코어는 검증만 — ADR-016 의 작성 모델 유지.
- 나가는 참조 모델은 파일 자체를 완결되게 한다(소스 파일만 읽으면 그 노드의 관계를 전부 앎). 미선택 참조 숨김과 결합하면 뷰어 병합 로직이 단순 집합 연산으로 끝난다.
- 트리 전체 임베드는 계획 그래프 규모(수십 노드)에서 지연 로딩의 복잡도가 불필요해 채택(ponytail).
- 임의 깊이는 데이터( children 경로)+뷰어(LevelPanel 재귀) 양쪽 모두 레벨 이름에 무관하게 설계해 모듈→클래스→메서드 이후의 계층도 규약·코드 변경 없이 들어온다.

## 대안 (Alternatives)

- **단일 파일 유지 + 뷰어 필터**: 파일 분할 요구를 충족 못 함. 배제.
- **공통 조상 파일에 엣지 저장**: 크로스 레벨 엣지의 단일 진실은 명확하나, 소스 노드 파일이 불완결해지고 승격·검증·병합이 복잡해짐. 나가는 참조 채택.
- **지연 로딩(자식 파일별 HTTP)**: 서버 엔드포인트·로딩 상태 추가. 현 규모에서 불필요. 배제.
- **레벨별 전용 뷰어(모듈 뷰/클래스 뷰 하드코딩)**: 2단계 고정으로 회귀. 임의 깊이 재귀 채택.

## 결과 (Consequences)

- core `graph.ts` 가 트리 프로토콜로 재작성(`coerceGraphLevelFile`·`loadGraphTree`·`collectGraphChildFiles`·경로 안전). `sections` API 제거.
- `persistence.ts`: `<base>-graph/` 경로 stageN 라우팅, 회귀 시 디렉터리 삭제, `promoteGraphTree`(도달 가능성 복사).
- 게이트 서버 `ViewerState.artifacts[].graph = {file, tree}`, 뷰어 `GraphView` 가 `LevelPanel` 재귀 드릴다운으로 재작성, `lib/graphTree.js`(순수 로직)+자체 테스트.
- Stage 2·3 designPrompt 가 트리 규약(3레벨: 모듈→클래스→메서드 포함) 지시; Feedback `structure` 체크리스트 갱신.
- 같은 레벨 노드 id 유일성은 프롬프트 지시 사항(뷰어 병합 전제); 코어는 파일 내 중복만 거부.
- 구 포맷 산출물은 그래프 블록 미표시(폴백 없음).
