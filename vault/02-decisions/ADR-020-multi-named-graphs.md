# ADR-020: 산출물당 다중 그래프 + 에이전트 자유 네이밍

## 상태

accepted ([[ADR-018-hierarchical-graph-tree]]·[[ADR-016-graph-json-externalization]] 확장 — 계층 트리 규약·참조 코멘트 프로토콜은 승계하고, "산출물당 그래프 1개 + 고정 이름" 제약을 폐지)

## 날짜

2026-08-12

## 맥락 (Context)

ADR-016·018 이래 그래프는 산출물당 1개였고 이름이 고정이었다: draft는 관례상 `draft-graph.json`, 게이트 오픈 시 참조 코멘트를 `<산출물 base>-graph.json`(예: `02-design-graph.json`)으로 **재작성**하고 그 고정 이름으로 승격. 세 가지 한계가 있었다.

1. **표현력** — 설계 산출물이 모듈 관계도·데이터 흐름·배포 토폴로지 등 성격이 다른 관계도 여러 개를 담고 싶어도 슬롯이 하나였다.
2. **이름이 내용을 못 담음** — `02-design-graph.json`은 단계 번호만 드러낼 뿐 그래프 내용이 무엇인지 말하지 않는다. 뷰어 헤더·코멘트·대화에서 "그 그래프"로만 지칭된다.
3. **경로 라우팅이 이름에 결합** — `paths.ts` 가 `-graph.json`/`-graph` 이름 패턴에서 소유 단계 md를 역추론해 `stageN/` 라우팅했다. 자유 이름에서는 이 추론이 성립하지 않는다.

사용자 요구: "그래프가 여러 개가 있을 수 있도록 만들어줘, 그래프.json이랑 폴더 이름을 고정하지 말고 에이전트가 그래프에 맞는 이름으로 정하도록."

## 결정 (Decision)

1. **다중 참조** — md 안 `<!-- graph: <루트 json 파일명> -->` 코멘트를 여러 개 허용한다. 코어 `graphRefFiles(md)` 가 전부 추출(문서 순서), 뷰어는 각 코멘트 위치에 해당 그래프를 인라인 블록으로 렌더링한다(기존 블록 파서·`GraphView` 재사용 — 참조마다 블록이 생기는 구조였음).
2. **에이전트 자유 네이밍** — 루트 json 파일명은 에이전트가 내용에 맞게 결정(예: `module-deps.json`). 제약: `.json`으로 끝나는 단일 파일명(경로 분리자·`..` 금지, `isSafeGraphName`), 같은 산출물 안에서 유일. 자식 폴더는 기존 규칙 그대로 루트 이름에서 `.json`을 뗀 값(`module-deps/`).
3. **이름 그대로 승격** — 게이트 오픈 시 각 참조 트리를 `stage<단계>/<에이전트 이름>`으로 승격한다. **md 참조 재작성 없음, 고정 이름 파생 폐지**(`graphJsonNameFor` 제거). `promoteGraphTree`는 쓰기 전 도달 가능 파일을 전부 메모리에 수집한 뒤 대상 디렉터리를 지우고 쓴다(src·dst 동일 안전).
4. **경로 라우팅 = 명시 단계 접두** — `stageSubdir` 는 이름 추론을 폐지하고 `stageN/` 접두 경로를 그대로 통과시킨다. 그래프 승격·서빙·무효화는 `stage<단계>/<이름>` 형태로 단계를 명시 전달. 산출물 md 자체는 기존처럼 파일명 매칭으로 라우팅.
5. **Stage 2 필수 규칙 = 1개 이상** — `checkRequiredGraph` 가 참조 0개·규약 위반(시도는 있으나 매치 실패)·참조 파일 누락·envelope 불량·**이름 중복**을 각각 구분된 메시지로 거부한다. 개수 상한 없음. Stage 1·3 선택 규칙 불변([[ADR-019-stage-2-graph-required]] 승계).
6. **무효화는 md를 읽고 삭제** — `invalidateArtifactsAfter` 는 삭제 전 md에서 참조를 추출해 `stageN/<이름>` + 자식 디렉터리를 지운다(이름 추론 불가).
7. **구 산출물 호환** — 기존 고정 이름(`02-design-graph.json`) 산출물은 md 참조가 그 이름을 가리키고 파일이 이미 `stageN/`에 있으므로 그대로 서빙된다. 마이그레이션 없음.

## 이유 (Rationale)

- 뷰어는 애초에 "참조 코멘트 → 그 위치의 블록" 구조라 다중 그래프가 블록 파서 수준에서는 무료였다. 진짜 비용은 승격·서빙·무효화의 이름 결합이었고, 명시 단계 접두로 한 번에 끊었다.
- 이름 추론(패턴 → 소유 md → 단계)은 데이터가 아닌 관례에 의존한다. 관례를 깨는 순간(자유 이름) 깨지는 코드는 설계 결함이다. 단계를 아는 호출측이 접두를 붙이는 것이 단순하고 견고하다.
- 승격 시 이름 보존은 md 재작성 경로를 통째로 없앤다 — 재작성이 없으면 코멘트 파손·드릴프트(이름 불일치) 버그 클래스도 없다.
- 중복 이름 거부는 같은 폴더 내 슬롯 충돌 방지(단계가 달라도 draft 공유 폴더를 경유하므로).

## 대안 (Alternatives)

- **그래프마다 json·폴더 이름을 각각 자유 지정(참조 코멘트에 둘 다 명시)** — 배제. 문법·검증·뷰어가 복잡해지는데, 폴더명 = json명 − `.json` 규칙이 이미 정착돼 실익이 없다.
- **승격 시 단계 접두 이름으로 정규화(`02-design-<이름>.json`)** — 배제. 무충돌은 되지만 md 재작성이 남고 이름이 길어진다. 단계 분리는 폴더(`stageN/`)가 이미 담당한다.
- **이름 → 단계 매핑을 state.json에 저장** — 배제. md 참조 자체가 매핑인데 별도 상태는 드리프트 위험만 더한다.

## 결과 (Consequences)

- 산출물마다 내용 이름을 가진 그래프 여러 개가 각 참조 위치에 인라인 렌더링된다.
- `graphJsonNameFor` 제거, `paths.ts` 이름 추론 분기 제거, `plan-gate.ts` md 재작성 제거 — 고정 이름 개념이 코드에서 사라졌다.
- draft 그래프는 기존처럼 feature 루트에 남아 다음 사이클의 재작성 재료가 된다(승격은 복사).
- 기존 산출물은 무변경 호환. 새 규약 위반(중복 이름·경로 포함·`.json` 아님·파일 누락)은 자동 반려 메시지로 안내된다.
