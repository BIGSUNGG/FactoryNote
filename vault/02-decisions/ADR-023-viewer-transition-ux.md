# ADR-023: 단계 전환 UX — 대기 화면 제거 + 이전 단계 읽기 전용 보기

## 상태

accepted

## 날짜

2026-08-13

## 맥락 (Context)

뷰어(React SPA)는 사용자가 게이트 결정(확정/검토 요청 등)을 내리면, 에이전트가 다음 산출물을 준비하는 동안 **전체 화면 '다음 준비 중'(`PreparingScreen`)** 으로 전환해 기존 페이지를 가려 왔다. 세 가지 단점:

1. **맥락 이탈** — 고객은 확정 직후 하단 게이트 바 프레임(Fixed 게이트 바 + GNB)이 통째로 사라지고 검정 전체 화면으로 교체되며 기존 산출물을 더 이상 보지 못한다.
2. **준비 완료 판별이 '화면 전환'으로만 표현** — 준비 중임을 중앙 스피너로 보여주지만, 다음 단계가 쓰이는 동안 기존 페이지를 유지하면서 진행 상태를 알리는 방법이 없다.
3. **이전 단계 열람 불가** — 승인된 이전 단계 산출물은 `state.artifacts`(모든 `stage <= state.stage`)에 이미 포함돼 있으나, 뷰어는 현재 단계만 렌더(`find(a => a.stage === state.stage)`)하므로 이전 단계 계획을 다시 보려면 직접 문서를 찾아야 한다.

## 요구 (사용자)

1. **확정 버튼 로딩 연출** — 다음 단계로 넘어갈 때 대기 페이지가 뜨지 않고 기존 뷰어 페이지를 그대로 유지, 확정 버튼이 로딩 중인 것처럼 연출하며 다음 단계가 작성 완료되면 넘어간다.
2. **이전 단계 읽기 전용 보기** — 스테퍼로 이전 단계 계획을 **읽기 전용**으로 볼 수 있고(기존 "정정"(revert) 기능과 무관), 읽기 전용일 땐 해당 계획에 코멘트·채팅을 작성할 수 없다.

## 결정 (Decision)

### 1) 게이트 결정 시 페이지 유지 + 확정 버튼 로딩

- `App` 의 `onGate`/`onReview` 가 `setPhase("preparing")`(전체 화면 전환)을 제거하고 `setPending(true)` 로만 상태를 올린다.
- `applyState` 의 `gateOpen=false` 분기에서, **이미 `reviewing`(검토 페이지 표시 중)이면 phase 를 바꾸지 않고 유지**한다(처음 진입/준비 상태에서만 `PreparingScreen` 유지, 이제 실질적으로 거의 미사용).
- `pending` 상태 동안 게이트 바의 확정(`GateBar`) 버튼이 스피너 + "다음 단계 작성 중…" 로 연출되고 다른 액션(정정/검토/회귀타겟)이 비활성화된다.
- 게이트 재오픈(`gateOpen=true`, 다음/재작성 산출물 준비 완료) 시 `pending` 이 해소되고 `reviewing` 유지 상태에서 다음 단계로 자동 전환된다.

### 2) 이전 단계 읽기 전용 보기

- `App` 에 `viewStage`(읽기 전용 대상 Stage, `null`=현재) 추가. 스테퍼 클릭 → `setViewStage` 로 전환.
- `pickMarkdown`/그래프 조립을 `viewStage` 기준으로 재계산 — 즉 `state.artifacts` 의 해당 단계 md/그래프를 재사용(데이터·백엔드 변경 없음).
- `readOnly = viewStage !== null` 일 때:
  - `PlanPage.readOnly` — 코멘트 생성·범위 코멘트·블록 활성화 핸들러를 no-op(`commentFreeze`)으로 여겨, 코멘트 작성 채널을 완전히 잠금. `GateBar`(확정/수정/정정) 미렌더. `readonly-banner` 배너 표시 + "현재 단계로 돌아가기" 버튼.
  - `ChatSidebar.disabled` — 채팅 입력(textarea/send/블록 스코프 체크박스) 비활성. 헤더 읽기는 유지.
- 복귀: 스테퍼에서 '실제 현재 단계'(`state.stage`) 스텝 클릭 또는 배너 '현재 단계로 돌아가기' → `viewStage(null)` 로 게이트 바·채팅 재활성. `App.onSelectStage = (n) => n === state.stage ? setViewStage(null) : setViewStage(n)` — 스테퍼 경로와 배너 버튼 경로를 동일하게 만든다(회귀 수정: 처음엔 스테퍼 클릭이 `setViewStage(단계번호)`만 해 `viewStage !== null` 이 유지되어 배너가 안 사라졌음).
- **스테퍼 작성 여부는 실제 서버 단계 기준으로 분리**(회귀 수정): `stagesFor(viewed, real)` — 작성 여부(`real`=`state.stage`)와 현재 보고 있는 단계(`viewed`=`curStage`)를 두 축으로 분리한다.
  - `s.n > real`: 아직 작성 안 됨 → `locked`(선택 불가).
  - `s.n === viewed`: 지금 보고 있는 단계 → `real === viewed` 면 `current`(편집 가능), 아니면 `view`(읽기 전용).
  - 그 외(작성됨·승인됨): `done` — 클릭으로 해당 단계 이동/복귀 가능.
  - 즉 이전 단계를 읽기 전용으로 봐도, 그보다 뒤이면서 이미 작성된 실제 단계들은 `done`(작성됨·선택 가능)으로 남아 '아직 안 쓴 단계(locked)'처럼 흐려 보이지 않는다.

**명시적 비목표**: 이전 단계 보기는 산출물 내용을 전혀 바꾸지 않는다(기존 `revert`/`modify` 워크플로 무관). 이전 단계에 대한 *수정*(코멘트→에이전트 수정 반영)은 기존 정정(revert) 기능으로 처리하며, 읽기 전용 보기는 참고용 조회 목적에만 쓴다.

## 대안 (Alternatives)

- **전체 화면 유지 + 오버레이 스피너** — 페이지 유지는 되지만 게이트 바 프레임이 유지되어야 한다는 요구를 미반영. 중앙 스피너가 페이지 위를 덮어 읽기 방해. 기각.
- **이전 단계를 별도 라우트/새 화면으로** — `state.artifacts` 에 이미 있으므로 새 라우팅 인프라 불필요. 스테퍼 클릭 전환(최소 변경) 채택.
- **이전 단계에 '수정' 허용** — 요구가 "읽기 전용" 이므로 배제.

## 결과 (Consequences)

- 긍정: 확정/검토 중에도 GNB + 게이트 바 프레임이 유지되어 맥락이 깨지지 않음. 준비 진행을 확정 버튼 로딩으로 명시. 이전 단계 참조를 터미널 없이 즉시 확인 가능. 백엔드·core 무변경(뷰어 전용).
- 부정/위험: `PreparingScreen` 이 거의 미사용이 되어 진행 상황을 넓은 화면으로 알리던 수단이 약화 — 초기 로드(first 진입)와 서버 미반응 순간에만 남는다. 채팅은 SSE push 로 실시간 갱신되므로 메시지 목록은 유지됨(입력만 잠금).
- 회귀 테스트: `App.test.jsx` 4건 — (1) 확정 후 `gateOpen=false` 여도 페이지 유지 + 확정 버튼 로딩(스피너/비활성) + 재오픈 시 로딩 해소, (2) 이전 단계 스테퍼 클릭 시 읽기 전용(게이트 미렌더·전송 버튼 비활성) + "현재 단계로 돌아가기" 복귀 시 재활성, (3) 읽기 전용에서 실제 현재 단계 스테퍼 클릭 시 배너·게이트·채팅 재활성(회귀 수정), (4) Stage 2 에서 미작성 Stage 3 만 `locked`·Stage 1 `done`·Stage 2 `current`(작성 여부 분리 검증). 자체체크 157 pass.
