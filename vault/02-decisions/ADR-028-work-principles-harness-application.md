# ADR-028: 4대 작업 원칙의 하네스 적용 방식

## 상태

accepted

## 날짜

2026-08-18

## 맥락 (Context)

사용자의 4대 작업 원칙(추론 자제·미래지향·문서주의·비판적 사고)을 pi 하네스에 적용해 에이전트가 매 세션 따르게 해야 한다. pi는 프롬프트 층(AGENTS.md·SYSTEM.md), 스킬, 확장 훅, 하드 게이트(도구 차단) 등 여러 강제 수준을 제공한다([[pi-harness-engineering-surfaces]]). 과도한 추론 방지(원칙 1)와 과잉 설계 방지(원칙 2의 긴장)를 동시에 만족하는 수준 선택이 필요하다.

## 결정 (Decision)

1. **범위**: 이 프로젝트에만 적용한다(`AGENTS.md` + `.pi/skills/` 원칙별 4스킬 + `.pi/extensions/work-principles.ts`).
2. **강제 수준**: 프롬프트(AGENTS.md)와 스킬로 유도하고, 문서주의 원칙만 확장 훅으로 리마인드한다(코드 변경·문서 미변경 실행 종료 시 알림). 도구 차단 같은 하드 게이트는 만들지 않는다.
3. **질문 임계값**: 주요 결정(아키텍처·사용자 가시 동작·되돌리기 힘든 선택)만 `ask_user_question`으로 질문하고, 사소한 구현 세부사항은 에이전트가 진행 후 보고한다.

## 이유 (Rationale)

- AGENTS.md는 매 프롬프트 구성에 자동 로드되어 최소 토큰으로 상시 적용된다.
- 스킬은 절차(질문·검토 체크리스트)를 필요할 때만 로드해 컨텍스트를 아낀다.
- 훅 리마인더 중 문서주의만 기계적으로 판정 가능(파일 경로 분류)하다 — 나머지는 판단 영역이라 프롬프트 유도가 적절하다.
- 하드 게이트는 오탐 시 긴급 작업을 막고 신뢰를 잃는다. FactoryNote의 "게이트는 사용자만" 철학과도 어긋난다(여기선 사용자가 직접 검토).

## 대안 (Alternatives)

- **매 턴 시스템 프롬프트 주입 훅**: AGENTS.md 로드와 중복되어 토큰 낭비 — 배제.
- **하드 게이트(문서 미작성 시 편집 차단)**: 강제력 최대이나 오탐·방해 위험 — 후속 후보로만 기록.
- **글로벌 적용(`~/.pi/agent/`)**: 문서주의가 vault/ 등 프로젝트 종속이라 분리 복잡 — 배제(사용자 결정).

## 결과 (Consequences)

- 매 세션 원칙 자동 적용, 위반은 리마인더로만 경고(차단 없음).
- 훅의 파일 경로 분류(vault/ 등 = 문서) 기준이 어긋나면 오탐 — 기준은 확장 상단 상수로 집중.
- 후속: 원칙 4의 `agent_settled` 체크리스트 출력, pi-guardrails 중복 점검은 필요 시 별도 ADR로.
