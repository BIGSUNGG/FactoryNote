# ADR-030: 에이전트 가독 문서 구조·작성 컨벤션

> **TL;DR**: 문서에 TL;DR 요약을 선행하고, 문서 유형별 안정적 섹션 어휘를 유지하며, frontmatter(updated·tags)를 필수로 하고, Home.md에 에이전트 읽기 지도를 둔다. 사람이 읽는 순서가 아닌 에이전트의 검색·스캔 순서로 문서를 설계한다.

## 상태

accepted

## 날짜

2026-08-18

## 맥락 (Context)

vault/ 문서는 한국어 산문 중심으로, 에이전트가 필요한 정보를 찾으려면 전문을 읽어야 했다. 문서 수가 60여 개로 늘면서 스캔 비용이 커졌고, 에이전트 친화적 구조(요약 선행·안정적 어휘·기계적 metadata)가 필요했다. 내용 자체는 성숙했으므로 **구조·작성법만** 바꾸고 의미는 보존해야 했다.

## 결정 (Decision)

1. **TL;DR 선행**: 실질 내용 문서(로그·인덱스 제외)는 H1·서론 바로 아래 `> **TL;DR**:` 블록(3문장 이내)을 둔다.
2. **안정적 섹션 어휘**: 문서 유형별 표준 H2 어휘를 고정한다(ADR: 상태·날짜·맥락·결정·이유·대안·결과·참고 / 문제: 현상·재현·원인·조치·영향·교훈 / 조사: 요약·증거·결론 / 설계: 단계 산출물 번호 유지).
3. **frontmatter 필수**: `updated`·`tags` 선택 권장 → 필수로 격상. `updated`는 문서 마지막 수정일.
4. **에이전트 읽기 지도**: Home.md 상단에 목적별 읽기 순서(오리엔테이션→구현→결정→사용→개발→문제→최근 작업).
5. **결론 먼저 쓰기**: 문단·섹션은 결론/요약을 먼저, 근거를 나중에.
6. 반영 위치: `90-meta/Doc-Conventions.md` · `.pi/skills/doc-workflow` · 템플릿(`adr.md` TL;DR 추가, `feature-doc.md` 신규) · 핵심 문서 5종 패턴 적용.

## 이유 (Rationale)

- 에이전트는 문서를 순독하지 않고 스캔·검색한다. 요약 선행과 안정적 제목 어휘는 읽기 전에 문서 가치를 판정하게 한다.
- frontmatter의 `updated`는 신선도 판정의 기계적 근거 — 권장으로는 누락이 발생한다(실제로 README.md 누락 발견).
- 읽기 지도는 "처음 온 에이전트가 어디서 시작하는가"를 명시해 진입 비용(orientation tax)을 줄인다.
- 내용 재작성 없이 구조만 바꿔 가역적이고 위험이 낮다.

## 대안 (Alternatives)

- **영문 번역**: vault 본문은 인간 사용자용이라 한국어 유지(기존 컨벤션). AI 판독 산출물(AGENTS.md·스킬·훅)은 이미 영어.
- **자동 생성 인덱스(graphify 등)**: 재생성 산출물은 진실의 원천이 될 수 없음([[ADR-001-documentation-system]]). 수기 지도가 기준.
- **전 문서 전면 재작성**: 의미 변경 위험·검토 비용 과대 — 핵심 문서 5종만 패턴 적용, 나머지는 작성 시점 규칙 적용.

## 결과 (Consequences)

- 신규 문서는 TL;DR + frontmatter 필수. 기존 문서는 수정 시 보강(점진 적용).
- TL;DR과 본문이 어긋나면 TL;DR을 본문 기준으로 고친다(요약은 본문의 종속물).
- 문서 유형별 어휘가 고정되어 자유로운 제목 실험은 제한됨 — 스캔 안정성과의 교환.
