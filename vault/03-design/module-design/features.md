# 모듈 설계 페이지 핵심 기능 — 관계도와 노드/엣지 코멘트

FactoryNote Plan 뷰어의 **Stage 3(모듈 아키텍처)** 산출물 페이지에 반드시 포함되어야 하는 기능을 정의한다. React 목업(`prototypes/plan-page-mockup/`의 `#/modules`)에서 동작을 검증했으며, 향후 본 구현에서도 이 사양을 준수해야 한다.

> plan 페이지([[core-features]])가 마크다운 **문서** 중심이라면, 모듈 설계 페이지는 **관계도(그래프)** 중심이다. 둘 다 같은 블록/노드 코멘트 → '수정 지시' 일괄 적용 모델을 공유한다.

> **배경**: Plannotator 분석([[plannotator-plan-page]])에서 확인한 구조 시각화 필요성 + FactoryNote 6단계 모델([[multi-agent-pipeline]]). 모듈 의존 관계는 설계 검토의 핵심이므로, 노드(모듈)뿐 아니라 **엣지(의존 A→B)까지 검토·코멘트 대상**이어야 한다.

---

## 기능 1 — 모듈 의존 관계도 렌더링

### 요구

산출물(모듈 구조도)을 **노드-엣지 그래프**로 렌더링한다. 모듈 간 의존 방향이 한눈에 보여야 한다.

### 사양

- **자동 레이아웃**: 노드 위치는 수동 좌표가 아닌 레이아웃 엔진에 위임(목업은 [mermaid](https://mermaid.js.org/) flowchart). 본 구현은 mermaid 또는 동등 그래프 라이브러리.
- **모노톤 톤**: 토큰에 맞춰 노드(흰 배경·검정 보더)·엣지(검정 선)·화살표. 계층(API·Service·Repository·Util·External)은 색이 아닌 **라벨/위치**로 구분.
- 노드는 모듈명 + 외부 시스템(예 DB)은 다른 모양(실린더).
- **데이터 주도**: 모듈(`MODULES`)과 의존(`DEPS`) 데이터 구조로부터 그래프가 생성. 하드코딩된 이미지 ❌.

---

## 기능 2 — 모듈(노드) 상세·코멘트

### 요구

그래프의 **모듈 노드를 클릭**하면 상세(계층·역할·의존 목록)와 코멘트를 확인·입력한다. 블록 코멘트([[core-features]] 기능 1)와 같은 원칙.

### 사양

- 노드 클릭 → 우측 상세 패널.
- 상세: 모듈명 · 계층(API/Service/...) · 역할 설명 · **관련 의존 목록**(나가는/들어오는).
- 코멘트는 모듈 단위(`comments[모듈명]`), pending 큐에 쌓임.
- 의존 목록의 모듈명을 클릭하면 해당 모듈로 이동(그래프 탐색).
- 노드 hover 시 시각 강조(opacity 등)로 클릭 가능 힌트.

---

## 기능 3 — 의존(엣지 A→B) 상세·코멘트 (핵심 차별점)

### 요구

**의존 관계 자체**(A→B)에 대한 설명과 코멘트를 확인한다. 노드(모듈)보다 세밀한, **관계 단위** 검토.

### 두 진입점 (둘 다 지원)

1. **그래프 화살표 클릭** — mermaid 엣지(path) 클릭 → 해당 의존 상세.
2. **모듈 상세의 의존 행 클릭** — 모듈과 관련된 의존(나가는/들어오는) 각 행 → 의존 상세. (그래프 엣지 클릭이 불안정할 때의 안정적 인터페이스)

### 의존 상세 패널

- `from → to` 표시 (양쪽 모듈명 클릭 시 해당 모듈로 이동 가능).
- **의존 설명**(DEPS 데이터의 `desc`): "비밀번호 bcrypt 해싱 위임" 등 관계의 목적.
- 코멘트 리스트 + 입력. 코멘트는 `comments["A->B"]` 키로 저장.

### 의존 목록 (모듈 상세 내)

선택 모듈과 관련된 의존을 두 그룹으로:

- **나가는 (→)** : `→ HashUtil · 설명 · 💬N`
- **들어오는 (←)** : `← AuthController · 설명 · 💬N`

각 행의 설명·코멘트 수가 보이고, 클릭 시 의존 상세로 전환.

### 데이터 모델

```js
DEPS = {
  "AuthService->HashUtil": { from: "AuthService", to: "HashUtil", desc: "비밀번호 bcrypt 해싱 위임" },
  ...
}
```

의존 식별자 = `"${from}->${to}"`. 엣지 코멘트의 `targetId`로 사용.

---

## 코멘트 → 일괄 적용 (수정 지시 게이트)

- 모듈 코멘트·의존(엣지) 코멘트는 같은 pending 큐.
- 하단 **'수정 지시 (N)'** 버튼 — N = 모든 pending 코멘트 수. 클릭 시 일괄 applied.
- **직접 편집 금지** (FactoryNote 5대 원칙 — [[project-identity]]). 코멘트 → Design Agent가 일괄 반영.

## 향후 본 구현 필수 요구사항 (체크리스트)

### 관계도 렌더링

- [ ] 노드-엣지 그래프로 모듈 의존 렌더링 (자동 레이아웃)
- [ ] 모듈·외부시스템 모양 구분
- [ ] `MODULES`/`DEPS` 데이터로부터 그래프 생성 (하드코딩 이미지 ❌)
- [ ] 톤 토큰 준수 (계층은 색 아닌 라벨/위치)

### 모듈(노드) 코멘트

- [ ] 노드 클릭 → 상세(계층·역할·의존 목록) + 코멘트
- [ ] 의존 목록의 모듈명 클릭 → 모듈 이동 (그래프 탐색)
- [ ] 노드 hover 시 클릭 가능 힌트

### 의존(엣지) 코멘트 (필수)

- [ ] 의존 데이터(`DEPS`)에 설명(`desc`) 포함
- [ ] **그래프 화살표 클릭** → 의존 상세
- [ ] **모듈 상세의 의존 행 클릭** → 의존 상세 (안정적 fallback)
- [ ] 의존 상세: `from→to` + 설명 + 코멘트(`comments["A->B"]`)
- [ ] 모듈 상세에 나가는(→)/들어오는(←) 의존 그룹 표시 + 설명·코멘트 수

### 공통

- [ ] 모듈·의존 코멘트 같은 pending 큐 → '수정 지시' 일괄 applied
- [ ] 직접 편집 금지 (5대 원칙)

## 한계 (본 구현 과제)

- **mermaid 엣지 클릭은 path 순서 매핑**이라 레이아웃/버전에 따라 불안정. 모듈 상세의 의존 목록이 안정적 인터페이스. 본 구현은 그래프 라이브러리의 엣지 클릭 API를 직접 사용해 안정화해야 한다.
- mermaid는 외부 의존(번들 크기). 본 구현에서는 오프라인/번들 최적화 검토.
