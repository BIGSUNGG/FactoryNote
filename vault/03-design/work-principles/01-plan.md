# 4대 작업 원칙 하네스 적용 — 기획

## 사용자 요청

다음 4원칙을 pi 하네스 엔지니어링으로 적용하여, 이 프로젝트에서 일하는 에이전트가 매 세션 따르게 한다.

1. **추론 자제** — 추가로 정하거나 알아야 할 부분을 스스로 추론해 정하지 말고 사용자에게 질문하여 진행.
2. **미래지향** — 확장성·유지보수성을 고려해 객체지향 원칙을 따르고 코드를 최대한 모듈화.
3. **문서주의** — 사용자가 요청한 모든 것(기획)과 구현한 내용(문서)을 문서로 작성하고, 처리 전 관련 문서를 참고.
4. **비판적 사고** — 사용자 요청과 구현 완료 내용을 비판적으로 검토하고, 좋지 않은 부분은 그대로도 괜찮은지 사용자에게 확인.

## 사용자 결정 (질문으로 확정 — 원칙 1 적용)

| 결정 사항 | 선택 |
| ------ | ------ |
| 적용 범위 | 이 프로젝트만 (`.pi/` + `AGENTS.md` + `vault/`) |
| 강제 수준 | 프롬프트+스킬 유도를 기본으로 하고, 필요한 원칙은 훅으로 리마인더 (하드 게이트 없음) |
| 질문 임계값 | 주요 결정(아키텍처·사용자 가시 동작·되돌리기 힘든 선택)만 질문, 사소한 구현 세부사항은 진행 후 보고 |

## 구현 산출물

1. `AGENTS.md` — "4대 작업 원칙" 섹션 추가 (매 세션 자동 로드).
2. `.pi/skills/` 원칙별 4스킬(ask-before-guess · future-proof-code · doc-first-workflow · critical-review) — 질문·모듈화·문서·검토 절차.
3. `.pi/extensions/work-principles.ts` — 문서주의 리마인더 훅: 코드 파일 변경이 있는데 문서(vault/·AGENTS.md·skills) 변경이 없는 실행 종료 시 알림.
4. 문서 — 본 기획, [[ADR-028-work-principles-harness-application]], 조사노트 [[pi-harness-engineering-surfaces]], 구현 기록 `02-implementation.md`, Changelog·Dev-Log.
